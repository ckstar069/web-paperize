# web-paperize V0.2 规划

> 日期：2026-09-10 · 前置：V0.1 已封板于 `e860821`，通用 PDF pipeline 不再修改（除非 V0.2 实现发现真实 regression）。
> 本文档是 V0.2 的唯一规划文档；调查证据来自四个开源项目的 source-level 审计与本机实验。

## 1. ChatGPT / 虚拟化 DOM 专项调查

### 1.1 审计对象

| 项目 | License | 形态 | 路线 |
| --- | --- | --- | --- |
| [Cocoanetics/ChatGPTExporter](https://github.com/Cocoanetics/ChatGPTExporter) | MIT | Chrome/Safari 扩展 | B：页面上下文直取 endpoint |
| [pionxzh/chatgpt-exporter](https://github.com/pionxzh/chatgpt-exporter)（用户补充推荐） | MIT | Tampermonkey 脚本 + 扩展，2022 年至今持续维护 | B + 最成熟的 materialize 参考 |
| [yesooner/chatgpt-conversation-export-extension](https://github.com/yesooner/chatgpt-conversation-export-extension) | MIT | Chrome 扩展 | A：debugger 网络捕获 |
| maks-bond/chatgpt-conversation-exporter | **无 LICENSE** | 扩展 | B（metadata-first）+ C（DOM 兜底）——仅思想参考，禁复制代码 |

### 1.2 三条获取路线对比

| 维度 | A：网络捕获 | **B：endpoint 直取（推荐）** | C：DOM 反向滚动 |
| --- | --- | --- | --- |
| 完整性 | ✅ 服务器响应，含全部分支 | ✅ 同一数据（`/backend-api/conversation/{id}` 即页面数据源） | ⚠️ 依赖虚拟化器逐段 hydration，长会话耗时且可能不完整 |
| 刷新页面 | **必须**（`Page.reload ignoreCache`） | **不需要** | 不需要 |
| 私有接口敏感度 | 低（只按内容特征 `mapping+current_node` 识别，不依赖 URL 模式） | 高（依赖 `/api/auth/session` 与 conversation endpoint 形状） | 低（DOM）但 UI 改版即碎 |
| 登录态 | 页面自己请求，零处理 | 页面同源 fetch 自带 cookie；token 仅内存中使用 | 同 A |
| host permission | 无（debugger） | **无**（fetch 在注入的页面上下文执行，ISOLATED world 即可——Cocoanetics 实证，不需要 MAIN world） | 无 |
| 失败检测 | 弱（45s 超时 + 响应嗅探） | **强（HTTP 状态码即失败信号）** | 弱（无完成判据） |
| 副作用 | 刷新破坏用户现场（滚动位置/未发送输入） | 无 | 滚动后需恢复 |
| 许可证 | MIT | MIT（两个独立实现互证） | maks-bond 无 LICENSE |

**结论：B 为主路线，C 为兜底，A 不采纳**（唯一独有价值是 endpoint 形状剧变时的替代获取，先不实现）。三个 MIT 项目对 B 路线独立实现互证，稳定性可信。

### 1.3 会话数据的关键事实（materialize 必须处理）

来自 Cocoanetics/pionxzh 的实现（这些是"完整数据"里仍然存在的坑）：

1. **活动分支**：`mapping` 是树（含重新生成的废分支）；正确路径 = `current_node → parent → … → root` 反转。
2. **可见性过滤**：跳过 `metadata.is_visually_hidden_from_conversation / is_hidden / hidden / is_redacted`。
3. **引用两代格式**：旧式 `【4†(来源)】` + 新式私有码位分隔符 `U+E200…U+E201`。
4. **旋转混淆键**：`{{file:…}}` 占位符的文件名藏在 metadata 里**键名会轮换**（如 `n7jupd_crefs`）——必须按值形状扫描，不能按键名。
5. **Canvas 文档**：内容在 `canmore.create_textdoc`（全文）与 `canmore.update_textdoc`（正则补丁）的工具消息里，需回放补丁重建。
6. **图片/附件**：`image_asset_pointer`（`sediment://`/`file-service://` 指针，需带 Bearer 换取下载 URL）、代码解释器 `sandbox:` 路径。
7. **特殊会话**（pionxzh）：分享页（`__share__` 前缀）、临时会话（id 不在 URL，靠 `/backend-api/f/conversation` 流识别）、项目/gizmo 会话。
8. **LaTeX**：正文含 `$$…$$`/`\[…\]`，处理 markdown 时需占位符保护（pionxzh 的 `╬n╬` 方案）。
9. **ChatGPT 滚动根是 `[data-scroll-root]` 内层容器，不是 window**（maks-bond）——C 兜底与通用 prepare 都要知道。

### 1.4 materialize 设计（本项目的新增工作，无人做过 PDF 版）

```
conversation JSON
  → 过滤 + 活动分支重建（§1.3-1/2）
  → 消息渲染管线（§1.3-3/4/5/6/8）：
      代码块（复用 V0.1 pre-wrap 打印 CSS）、表格、引用→脚注区、
      图片→内嵌下载、Canvas/附件→文末附录块、LaTeX V0.2 先保原样文本
  → 生成干净的可打印 DOM（自有 chat 模板，非复刻 ChatGPT UI）
  → 注入当前页（body 子节点全部隐藏——记 undo；模板根进 injected 清单）
  → 走现有 capture pipeline（screen media + printToPDF）
  → restore（现有 undo log 机制，零新代码）
```

设计原则：materialize 产物是**普通网页**，因此复用 V0.1 的全部打印管线与恢复机制；失败时（endpoint 401/404、无消息）显式报错并回退到普通整页导出（当前 DOM 有什么就导什么，行为不劣于 V0.1）。

### 1.5 隐私表述修订（硬要求）

路线 B/C 是向 **chatgpt.com 自身 origin** 发起请求（与页面自身行为一致），不能再宣称"扩展完全不产生网络请求"。承诺改为：

> 无第三方服务器、无遥测、会话内容不发送给 web-paperize 或任何第三方；对当前网站的请求仅为读取你正在查看的会话数据（与页面自身加载行为相同）。

README/popup 文案在 P2 批次落地时同步修改。

### 1.6 site-adapter 边界（架构原则）

```
src/adapter/
├── index.js          # getAdapter(url)：按 canHandle 选择，普通网页返回 null
└── chatgpt/
    ├── detect.js     # canHandle(url)：chatgpt.com(/c/<uuid>|/g/<gizmo>/c/<uuid>)
    ├── acquire.js    # 注入页面的取数函数（ISOLATED world，自包含，同 prepare.js 约束）
    └── materialize.js# conversation JSON → 可打印 DOM 模板
```

- service-worker 在 `capture` 前查询 adapter；`acquire()` 失败 → 按普通网页继续。
- **通用 `prepare.js` 不出现任何 ChatGPT 特例**；不为 Claude/Gemini 预留框架，只保证第二站点接入时新增目录即可。

## 2. V0.2 通用功能（第一批实现）

三项全部复用现有 pipeline，不新建捕获架构。参考：page2pdf 的 picker（hover 高亮 + 方向键扩缩选区）与 isolateElement（沿祖先链隐藏兄弟、保留元素自身样式、fit 纸张自适应宽）、isolateSelection（选区克隆到宿主容器继承样式）。

### 2.1 Element / Selection 导出
- popup 新增入口 + 右键菜单（需新增 `contextMenus` 权限，评审时确认）。
- 复用 undo log：隐藏兄弟记录在案，导出后完整恢复。
- 完成判据：benchmark 夹具新增 picker 用例；GitHub 仓库页选 README 区域导出，内容完整、样式保留、页面恢复。

### 2.2 单张连续长页
- 测量法：`paperHeight = contentHeight×scale/96 + 2×margin`（V0.1 定点迭代已保证宽度测量正确）。
- **本项目实测高度上限（2026-09-10，Chrome 152.0.7977.83，headless CDP printToPDF）**：
  - ≤910in（65520pt）单页成功；≥915in 显式报错 `Printing failed`。
  - 边界即 **65536pt（2^16）≈ 910.2in ≈ 87381 CSS px**（PDF 后端 16 位边界）。
  - 上游数字修正：pdfsnap"800in 以上静默失败"→ 实为 ≈910in 且**显式报错**；page2pdf 200in、screen-to-pdf 1000in 均非实测事实。
- 项目常量取保守值 **900in（86400 CSS px）**：超限或打印失败 → 自动回退 A4 分页并提示。
- 完成判据：构造 300in/900in/超限三档测试页各导出一次，前两档单页完整、超限档自动分页。

## 3. Snapshot 双引擎（本轮只定接口，不实现）

- 触发：默认 Text；用户显式切换，或 Text 输出后检测到 `<canvas>/<video>` 占比超阈值时建议（不做自动重打，避免双倍耗时）。
- 接口：`capture.js` 内 `captureText/captureSnapshot` 平级函数；prepare/settings/download **单一来源共享**，两引擎不各抄一份。
- 范围预估：借鉴 page2pdf 切片 + pdf-writer（MIT，THIRD_PARTY_NOTICES 登记后引入）。
- 完成判据（实现批次）：夹具新增 canvas 用例；WebGL 示例页快照导出视觉一致。

## 5. 对 V0.1 的修改边界

允许改动：`capture.js`（入口分派 adapter/scope/单页）、`service-worker.js`（消息路由）、`settings.js`（新字段）、popup UI。**不改动**：`cdp.js`、`prepare.js` 既有函数语义（只允许新增函数）、`download.js`、manifest 既有权限语义（新增 `contextMenus` 需评审确认）。出现 regression 时以最小修复为原则并记录。
